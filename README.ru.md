# Linspector

Перехватчик Fetch, XHR, WebSocket и SSE прямо на странице со встроенным набором инструментов для тестирования безопасности.

[English](README.md) | Русский

> Дисклеймер: Linspector написан исключительно в образовательных целях и для авторизованного тестирования безопасности. Используйте его только на системах, которыми вы владеете или на тестирование которых у вас есть явное письменное разрешение. Активные инструменты (Repeater, Tamper, breakpoints, библиотека пейлоадов) отправляют и изменяют реальные запросы, поэтому никогда не направляйте их на системы, которые вам не разрешено тестировать. Авторы не несут ответственности за неправомерное использование.

## Возможности

- Живой перехват Fetch и XHR с заголовками запроса и ответа, телом, payload и таймингами.
- Перехват WebSocket и Server Sent Events с журналом кадров по каждому соединению.
- Запросы сгруппированы по секторам по хосту, у каждого есть Archive All и Clear, а также History с восстановлением и удалением.
- Repeater для редактирования и повторной отправки любого запроса с экспортом в cURL, Python и Burp.
- Breakpoints, которые ставят на паузу подходящие fetch запросы для редактирования, пропуска или отбрасывания.
- Правила Tamper для автозамены в URL, теле или заголовках, с поддержкой регулярных выражений.
- Переключатель сессий с пресетами заголовков для быстрой проверки IDOR и нарушений контроля доступа.
- Пассивный сканер безопасности: декодирование и аудит JWT, поиск секретов и API ключей, обнаружение stack trace, аудит CORS и security заголовков.
- Инструменты атаки: библиотека пейлоадов XSS, SQLi, SSTI и SSRF, сравнение ответов и декодер JWT.
- Пересылка запроса на relay endpoint Burp Suite или Caido.
- Инспектор LocalStorage и cookie с аудитом атрибутов cookie.
- Живой поиск, фильтр по минимальному статусу, исключаемые домены, сохранение в LocalStorage и выбор темы.

## Проверки безопасности

| Уязвимость                        | Что это                                                                                                                                 | Как Linspector находит или тестирует                                                                                                                                   |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Слабости JWT                      | Токены с `alg: none`, слабым секретом HMAC или без `exp` и с истёкшим сроком позволяют подделать или переиспользовать сессию            | Пассивный сканер декодирует каждый Bearer JWT и помечает `none`, HMAC, истёкший `exp` и отсутствие `exp` или `iat`. В вкладке Attack есть ручной декодер и аудитор JWT |
| Утечка секретов и API ключей      | Ключи AWS, Google, Slack, GitHub и Stripe, приватные ключи или bearer токены в трафике дают прямой доступ к сервисам                    | Пассивный сканер прогоняет библиотеку регулярных выражений по телам запросов и ответов и сообщает о каждом совпадении с фрагментом-доказательством                     |
| Раскрытие stack trace             | Трассировки ошибок в ответах раскрывают фреймворки, пути к файлам и внутреннюю логику                                                   | Сканер обнаруживает stack trace Python, Node, Java и общего вида в телах ответов и создаёт находку                                                                     |
| Ошибки CORS                       | Wildcard `Access-Control-Allow-Origin` вместе с credentials позволяет любому источнику читать авторизованные ответы                     | Аудит заголовков проверяет CORS заголовки ответа и помечает wildcard источник, особенно вместе с `Allow-Credentials: true`                                             |
| Отсутствие security заголовков    | Нет CSP, X-Frame-Options, HSTS, X-Content-Type-Options или Referrer-Policy, что открывает clickjacking, MIME sniffing и downgrade атаки | Аудит заголовков проверяет каждый ответ и перечисляет отсутствующие заголовки с уровнем важности                                                                       |
| Небезопасные cookie               | Cookie без Secure, HttpOnly или SameSite можно украсть по HTTP, прочитать из скрипта или отправить cross site                           | Инспектор Storage перечисляет cookie и помечает каждый отсутствующий атрибут                                                                                           |
| IDOR и нарушение контроля доступа | Доступ к чужому объекту через подмену id или токена открывает данные, которые пользователь не должен видеть                             | Переключатель сессий хранит пресеты токенов, а Repeater повторяет тот же запрос от другой личности, чтобы сравнить выданный доступ                                     |
| XSS                               | Неочищенный ввод, отражённый или сохранённый и выполненный как скрипт, запускает код атакующего в браузере жертвы                       | Библиотека пейлоадов даёт векторы XSS, Tamper и Repeater внедряют их, а Response diff сравнивает ответы для поиска отражения                                           |
| SQL инъекция                      | Недоверенный ввод, попадающий в SQL запрос, позволяет читать или менять базу данных                                                     | Библиотека пейлоадов даёт пробы SQLi для Repeater, а Response diff подсвечивает изменения в поведении или времени ответа                                               |
| SSTI                              | Ввод пользователя, вычисляемый серверным шаблонизатором, может привести к удалённому выполнению кода                                    | Библиотека пейлоадов даёт пробы SSTI вроде `{{7*7}}` для отправки через Repeater и наблюдения за результатом                                                           |
| SSRF                              | Сервер загружает подконтрольный атакующему URL и может достучаться до внутренних сервисов и метаданных облака                           | Библиотека пейлоадов даёт цели SSRF вроде `127.0.0.1`, `169.254.169.254` и `file://` для Repeater                                                                      |

## Стек технологий

- TypeScript со строгими настройками компилятора.
- esbuild для сборки в content scripts Manifest V3.
- Shadow DOM для полной изоляции от страницы.
- Рендеринг на чистом DOM без рантайм зависимостей.
- Vitest для тестов, ESLint и Prettier для контроля качества.

## Архитектура

```
src/
  interceptor.ts        скрипт MAIN world: подмена fetch, XHR, WebSocket и SSE
  content.ts            вход ISOLATED world: шина, store и интерфейс
  core/                 модель данных, протокол шины, транспорт, id
  store/                состояние, настройки и хранилище LocalStorage
  tamper/               правила tamper и автозамены для интерцептора и интерфейса
  security/             jwt, секреты, аудит заголовков и оркестратор сканирования
  attack/               экспорт curl, python и burp, библиотека пейлоадов, diff ответов
  repeater/             повторная отправка запросов и пересылка на relay
  inspect/              доступ к LocalStorage и cookie
  utils/                цвета, форматирование, url и заголовки
  ui/                   контроллер панели, общие части и вкладки
```

Интерцептор работает в основном мире страницы, поэтому может обернуть настоящие сетевые API. Он передает записи и кадры потоков в изолированный content script через `window.postMessage` и получает обратно конфигурацию и решения по breakpoints на том же канале. Content script владеет store и рендерит панель внутри Shadow DOM.

## Установка и сборка

Требуется Node.js 18 или новее.

```bash
npm install
npm run build
```

Результат сборки находится в папке `dist/`.

## Загрузка в браузер

1. Откройте `chrome://extensions`.
2. Включите режим разработчика.
3. Нажмите Load unpacked и выберите папку `dist/`.
4. Откройте любую страницу и используйте плавающую кнопку в правом нижнем углу.

Нужен браузер на Chromium версии 111 или новее для content scripts в основном мире.

## Примечания по использованию

- Breakpoints применяются к fetch запросам. Правила Tamper и внедрение сессии применяются к fetch и XHR.
- Repeater отправляет запрос из контекста расширения с включенными cookie и следует правилам same origin страницы.
- Пересылка отправляет сериализованный запрос в формате JSON на endpoint из настроек. Направьте его на локальный listener Burp или Caido, принимающий JSON, либо используйте экспорт в Burp для вставки сырого запроса в Repeater. Экспорт в cURL поддерживает флаг прокси `-x`.
- Сканер пассивный. Он только читает трафик, который страница уже генерирует.
